- (capability) CAP-1 Parent account, PIN, Student Profiles, mode switching — parent creates account+PIN+profiles; shared device defaults Student Mode, PIN gates Parent View, silent 15-min idle expiry returns to Student Mode with every uncommitted parent input (draft edits, position, partial upload, grade-override-in-progress minus AI rationale) restored exactly after PIN re-entry, held server-side only. Bundles FR-1,2,3,4,34,35.
- (capability) CAP-2 Source Test upload — parent captures/selects 1-10 page photos (camera or library, freely mixed, library first-class when camera unavailable), reorders/retakes/deletes pages, classifies Subject+Grade Level, gets a one-time batch legibility check with per-page retake, and commits (spends one Upload Allowance only on success). Bundles FR-5,6,7,8,9a.
- (capability) CAP-3 Extraction and generation — system extracts structured Questions/Formats/Topics spanning all pages as one document (cross-page context preserved, uninterpretable content never guessed), persists the Extraction for reuse after photos expire, and generates 1-5 new non-verbatim Practice Tests matching the source's topic and format mix, plus weighted regeneration from one Weak Area Topic. Count is bounded/clamped server-side by remaining Generation Allowance, cost stated before confirm. Bundles FR-9,9a,10,11.
- (capability) CAP-4 Parent review and release — parent reviews every generated Question (answer, Topic) in one list, edits text/options/correct-answer or deletes, sets an optional pre-release timer (off by default, non-escalating 5min/1min/20s warnings), then releases (irreversible, makes it visible in Student Mode) or discards. Bundles FR-12,13,14,15.
- (capability) CAP-5 Taking a Practice Test — student sees released+completed tests as one flat unstarted-first list, answers each Question by its format (MC single-select, Fill-in-Blank inline input, Short Answer multi-line) with backward/forward nav and a question map reaching any Question directly, submits (confirmation naming unanswered count with a path back), and can retake (new Attempt, prior ones kept, only first counts to Mastery). Attempt survives backgrounding/refresh/offline; submission requires network and is never silently retried; a timer expiring offline auto-submits on reconnect graded at the expiry moment. Bundles FR-16,17,18,19,20,36.
- (capability) CAP-6 Grading, reveal, Explanations, flags, suppression, disputes — every Question carries exactly one of four grade states (correct/incorrect/unanswered/ungraded, single authoritative table) written per fixed rules; MC grades deterministically, Fill-in-Blank/Short-Answer grade by AI semantic match with a persisted rationale and graceful ungraded degradation; student gets immediate score+full answer key in test order; can request a cached on-demand Explanation (generation capped by allowance, reading never capped except suppression); can flag an Explanation (reaches Admin only once parent confirms) or dispute a grade (parent overrides in Attempt detail, recomputes score+Mastery, original AI grade+rationale retained, override visibly marked); parent can suppress a confirmed-flagged Explanation for their own child and get a free regenerated replacement (not reversible, stated as such). Bundles FR-37,21,22,23,24,24a,38,39,25.
- (capability) CAP-7 Analytics and Mastery — Topics free-form-emitted at generation are normalized onto one per-Subject canonical set (not per Grade Level) so one concept yields one Mastery value; per-Topic Mastery is a rolling 5-qualifying-Attempt window (correct/(correct+incorrect), retakes excluded); a Topic is a Weak Area below 60% Mastery with 5+ answered Questions; dashboard leads with Weak Areas, a per-profile activity summary and 5-Attempt score trend (each figure stating its own window), the Explanation Allowance counter, and surfaced disputes/flags; Mastery is never shown without its unanswered count; parent can drill into missed Questions per Topic and launch weighted regeneration. Bundles FR-26a,26,27,28,29.
- (capability) CAP-8 Admin configuration — an Admin manages the Subject/Grade-Level taxonomy (disable never destroys existing data, rename propagates by reference), assigns Account Tiers (effective immediately against the current period), and inspects per-account consumption on three counters against each account's own reset period plus the flagged-Explanation content-quality queue (Grade Level context, suppressed items stay listed). Bundles FR-30,30a.
- (capability) CAP-9 Data retention and deletion — Page Images (bytes, not just references) auto-delete 90 days after Source Test upload without breaking regeneration (Extraction persisted separately); parent can delete Page Images early (identical effect), delete a Student Profile (distinct from archive), or delete the whole Parent Account, each requiring account-password re-auth and an explicit cannot-be-undone confirmation naming what is destroyed, with no orphaned files left behind. Bundles FR-32,33.
- (capability) CAP-10 Account Tiers and allowance enforcement — every account carries one Tier (Free/Plus/Family/Internal, Admin-assigned only) fixing a Student Profile limit and three independently-tracked monthly allowances (Upload/Generation/Explanation, numbers in tiers.md companion) that reset atomically on the account's own calendar-month boundary in its stored timezone; consumption is charged only on successful production, never on request; hitting a cap hard-blocks naming tier/usage/reset date; AI grading and reading an already-generated Explanation are never blocked by any allowance (suppression is the sole carve-out). Bundles FR-31.
- (constraint) Hard OpenAI dependency, no provider abstraction layer in v0 — speed over insurance, accepted risk a provider change forces a refactor across Extraction/Generation/Grading/Explanation. Rules out any swappable-provider design.
- (constraint) Parent review gate (edit/delete/release) is mandatory between generation and any Question reaching a student — no auto-release path may exist.
- (constraint) Every AI call class (Extraction, Generation, Grading, Explanation) must run under provider terms excluding submitted content from model training — not just the vision call.
- (constraint) Page Images hard-delete 90 days after upload (bytes, not reference) with Extraction persisted separately so regeneration keeps working photo-free; rules out any design coupling regeneration to stored images.
- (constraint) One credentialed Parent Account per family; Student Profiles have no credentials; a shared device is bound to one Student Profile and PIN-gates Parent View — rules out per-child login and multi-parent sharing.
- (constraint) Score denominator = every presented Question (a blank costs the mark); Mastery denominator excludes unanswered Questions — the two are deliberately different measures and must never be unified into one number.
- (constraint) Every allowance block is a named hard stop (tier, usage, reset date) — never a silent failure or generic error; AI grading and reading an already-generated Explanation are never blocked by allowance at any tier.
- (constraint) Inherited stack is decided, not an open choice: Turborepo/pnpm workspaces, NestJS+Prisma+PostgreSQL API, Next.js+React+MUI web, JWT+argon2 hashing, local-filesystem image storage, Playwright E2E — exact versions and module boundaries are authoritative in the architecture-spine companion, not restated here.
- (constraint) Target WCAG 2.1 AA on student-facing surfaces; dark mode ships in v0 across both modes with every contrast pair verified in both — not a stretch goal.
- (constraint) Destructive actions (Student Profile deletion, Parent Account deletion, early Page Image deletion) require the account password, not the Parent PIN — the PIN gates a mode, never a destructive action.
- (note) Not a classroom tool — no teacher accounts, rosters, assignment distribution, or school-level anything.
- (note) Not a curriculum or content library — generates only from what a parent uploads; no question bank, no curriculum-alignment claim.
- (note) Not a grading system of record — scores are practice signal only, never a substitute for a teacher's grade.
- (note) Not a tutor — Explanations explain one Question with no conversational back-and-forth or chat.
- (note) Not gamified — no streaks, points, leaderboards, badges, or rewards, ever.
- (note) Not a document scanner — photos only; PDF and general OCR are out of v0.
- (note) Not multi-parent — one Parent Account per family in v0, no co-parent sharing.
- (note) No monetization, billing, or self-serve tier upgrade in v0 — Account Tiers exist and are enforced but carry no price; only an Admin assigns them.
- (note) No notifications of any kind in v0 (push or email on student completion) — the Analytics activity summary is the v0 answer to 'did my child do it'.
- (note) No native mobile apps, no offline test-taking beyond the FR-36 in-Attempt carve-out, no localization beyond English, no recall of a released Practice Test, and no per-family Weak-Area-threshold configuration in v0.
