## Intent

**Problem:** Student Results and parent Attempt detail both stack every `AnswerKeyRow` in one list, so a 20-Question paper is an endless scroll on the one-handed phone the PRD designs for — it hides where the wrong answers are, makes "go back to Question 7" a hunt, and violates EXPERIENCE.md's own ban on infinite scroll. Parent deep links from Grade disputes and Explanation flags already know the Question but land at the top of the page.

**Approach:** Page both surfaces one Question at a time behind a shared pager, mirroring Take Test's proven shape (UX-DR34, UX-DR39, UX-DR47): score header above, one answer-key row, a "Question N of M" position, Previous/Next (plus Left/Right arrow keys outside text entry), and a **results map** — grade vocabulary, not progress vocabulary — as a rail from `md` up and an overlay below. All rows stay mounted with the `hidden` attribute so every panel's open state survives a page turn; the current Question rides in `?q=<ordinal>`, replaced not pushed. Presentation only: no API, no schema, no new read.

## Boundaries & Constraints

**Always:**
- **Paging is client-side over the one existing response.** A page turn makes **no** request. The one-read-per-Attempt invariant and FR-22's view-triggered ungraded retry are untouched.
- **Every row stays mounted; non-current rows carry the `hidden` attribute.** This is what preserves each `ExplainPanel` / `DisputePanel` / `GradeReview` / `ExplanationReview` open state, loaded text and in-progress input across page turns, and what keeps hidden rows out of the assistive-technology tree. `ExplanationReview` holds nine pieces of unpersisted local state — unmounting is data loss.
- **One shared pager used by both surfaces**, parameterized by the rows, a per-row render callback, per-audience labels, and an optional footer slot. It takes its density from `theme.density`, never by importing `density` or `comfortableDensity` — the student surface is 48px, the parent 44px.
- **Results-map cells are real buttons** carrying the ordinal plus the Question's grade-state glyph in its grade-state frame, with the fixed grade label inside the accessible name as a full sentence, `aria-current` on the active Question, a newly-graded mark where the row has one, and an on-screen legend of only the grade states present. Grade vocabulary only. No percentage, no tally beyond the header.
- **Shared cell geometry is extracted from `QuestionMap`, not forked.** `QuestionMap`'s rendered output, behavior and copy must be byte-for-byte unchanged in its specs.
- `?q=<ordinal>` is written with a client-side **`router.replace`** (`{ scroll: false }`). Browser Back leaves the screen rather than walking Questions, and the client-side-only navigation is what keeps parent elevation alive (AD-18).
- The paged view is selected by matching `row.ordinal`, **never** by array position — a row whose stored Question vanished carries `ordinal: 0`.
- Arrow-key paging ignores events whose target is an `input`, `textarea`, `select` or contenteditable region, any held Alt/Ctrl/Meta/Shift, an open overlay map, and the ends of the range.
- On every page turn: focus moves to that row's Question heading, the position sentence is announced politely through the surface's **existing** live region, and **nothing animates**.
- The score header stays above the pager and does not repeat or re-announce per Question. Retake (student) and back-to-list (parent) stay below the pager, visible on every Question.
- Every new user-facing string lives in `copy/student.ts` or `copy/parent.ts`; second person to the child, third person to the parent. Both light and dark mode; no new colour, no colour alone.

**Block If:**
- A page turn cannot be made without an additional network read.
- Keeping all rows mounted proves impossible without unmounting panels (would silently destroy an in-flight parent decision).

**Never:**
- No API, DTO, Prisma schema, migration, or architecture-decision change. No new endpoint and no new field on the wire.
- Do not page the **analytics drill-down** (`parent/analytics/topics/[topicId]`) — it keeps the stacked list, already being a filtered subset across runs. Do not put paging inside `AnswerKeyRow` or anything the drill-down renders.
- Do not change `AnswerKeyRow`'s heading level: it stays `h4` (two specs pin it).
- Do not persist the current Question in `localStorage` or `sessionStorage` — the URL is the only legal carrier.
- No animation, transition, `Fade`/`Grow`/`Collapse`/`Zoom`, score count-up, or celebration.
- Do not teach `QuestionMap` any grade word, and do not reuse `QuestionMap` itself as the results map — its spec forbids every correctness word in its markup and forbids paging its cells.
- No `useMediaQuery` for the rail/overlay split — responsive `sx` only, both forms always rendered.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| First load, no `q` | Results with 12 rows, URL has no `q` | Question 1 shown, `q=1` written by replace, Previous disabled | No error expected |
| Valid deep link | `?q=7`, run has ordinal 7 | Question 7 shown on arrival; Previous and Next both enabled | No error expected |
| Out-of-range `q` | `?q=99` on a 12-row run | Question 1 shown, `q` replaced with `1` | Silent clamp, no alert |
| Non-numeric / empty `q` | `?q=abc`, `?q=` | Question 1 shown, `q` replaced with `1` | Silent clamp, no alert |
| Next at the last Question | On ordinal 12 of 12 | Next disabled; ArrowRight does nothing | No error expected |
| Arrow key while typing | Caret in a dispute textarea, ArrowRight | Caret moves; the page does not turn | No error expected |
| Arrow key with modifier | Shift+ArrowRight on the pager | Nothing happens | No error expected |
| Arrow key with overlay open | Overlay map open, ArrowLeft | Nothing happens | No error expected |
| Map jump below `md` | Overlay open, cell 5 pressed | Overlay closes, Question 5 shown, focus on its heading | No error expected |
| Panel state across a turn | Explanation open on Q3, go to Q4 and back | The explanation is still open with its text; **zero** requests fired by the turns | No error expected |
| Deep link with null ordinal | Dispute entry whose `questionOrdinal` is `null` | Link omits `?q=`; detail opens on Question 1 | No error expected |
| Ungraded still pending | A row is `Ungraded` | Its map cell shows the ungraded frame/glyph; the legend lists `Ungraded` | No error expected |
| Grading gap only | Zero gradable Questions | Header states the gap as today; the pager still pages every row | No error expected |

## Design Notes

**Why rows stay mounted and hidden rather than sliced.** `ExplanationReview` holds nine pieces of purely local state (`flagging`, `confirming`, `suppressing`, `regenerating` and four failure strings) with no persistence, and `ExplainPanel`/`DisputePanel` hold loaded text and typed input. Slicing the array would unmount them, so a parent who paged away mid-decision would lose it silently — including a failure message they had not read yet. Mounting everything and hiding all but one costs nothing (the rows are already in the one response) and makes the panel-survival acceptance criterion true by construction rather than by careful handling.

**Why `hidden` needs a CSS line.** The row root sets `display: 'grid'` in `sx`, which has higher specificity than the UA stylesheet's `[hidden] { display: none }`. Without the explicit rule the attribute would remove the row from the accessible tree while leaving it on screen — the worst of both:

```ts
sx={{
  display: 'grid',
  '&[hidden]': { display: 'none' },
  // A lone visible row has no row above it to be separated from.
  '&:not([hidden]) + &:not([hidden])': { borderTop: '1px solid', borderColor: 'divider' },
}}
```

**Why the geometry is extracted and the vocabulary is not.** `QuestionMap.spec.tsx:107-118` asserts its rendered markup matches none of `/score/`, `/%/`, `/correct/`, `/wrong/`, `/grade/`, `/right/`, and `:133-140` asserts it never pages its cells. Those are not incidental — they are the proof that no correctness leaks before submission. A single component serving both moments could not satisfy them. So the shared unit is the grid rule, the button `sx`, and the aria-hidden-digit / visually-hidden-sentence / `aria-current` structure; the glyph table, heading, summary, progress bar and legend stay with whichever vocabulary owns them.

**Why `announce` is injected.** The student surface announces through the app-wide `useAnnounce()` provider; the parent surface owns its own `role="status"` region, already shared with grade-override and flag outcome sentences. A pager that hooked one of them would either break the other surface or clobber an outcome the parent had not read. Taking a callback also keeps the pager hookless enough to stay assertable as a markup string, the way `AnswerKeyRow` is.

**Why the caller owns the URL.** Both pages already have a settled `useSearchParams` + `Suspense` shell convention to copy, and the parent page's spec forbids web storage outright. Keeping `router.replace` in the page means the pager has no router dependency, which is also what makes it testable without a Next.js harness — and `replace` rather than `push` is what keeps Back returning to the disputes list instead of walking twenty Questions.
