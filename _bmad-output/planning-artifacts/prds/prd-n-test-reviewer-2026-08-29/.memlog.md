- (decision) BLOCKER 1 RESOLVED — new FR for EXPLANATION SUPPRESSION, closing the gap where 5.1's accountability argument terminated in an Admin queue with no power to act. A parent-confirmed flag can SUPPRESS an Explanation on their own child's screen: it stops being served to that Student Profile, and the parent may request a regeneration which is NOT charged against any allowance (charging a parent to replace bad AI output the product generated would be indefensible). The Explanation remains retained and readable by the parent per FR-24a and still reaches the Admin queue as a content-quality signal per FR-30a — suppression is about what the child sees, not about erasing the record. Rationale: 5.1 justifies showing children unreviewed AI-generated content on the basis that accountability is after the fact via retention plus a parent flag, but the chain ran child sees it, flags it, parent confirms, Admin queue, nothing — FR-24 guarantees cached re-serving that is never blocked, FR-16 keeps the card visible indefinitely, and FR-38 states flagging removes nothing, leaving FR-33 profile deletion as the only remedy. The parent is the accountable adult everywhere else in this design (grade disputes, draft review, release gating) and this was the one place they held a flag that did nothing. Rejected: Admin-only removal, which leaves the parent unable to act tonight and depends on a single operator who may be asleep; and accepting the gap, which is a defensible v0 cut for most features but not for the safeguard that justified shipping Explanations ungated. CONSEQUENCES: FR-24's never-blocked cached re-serving needs a suppression carve-out; FR-38 must state that a confirmed flag can suppress; FR-16's indefinite card visibility is unaffected since only the Explanation is suppressed; regeneration must bypass the FR-31 Explanation Allowance including on Free.
- (decision) BLOCKER 2 RESOLVED (review-consistency C-1): the Attempt SCORE is computed over ALL PRESENTED Questions. An unanswered Question counts against the score exactly as a wrong answer does — '11/15' where 15 includes blanks. This matches every worked example already in the PRD (FR-20's First 11/15, UJ-2's 11/15) and matches a paper test, where a blank costs the mark. FR-37's 'never counted as a wrong answer' must therefore be NARROWED to Mastery only, and FR-23 must state the denominator rule explicitly rather than leaving it to be inferred. THE TWO INSTRUMENTS ARE DELIBERATELY DIFFERENT and this must be stated so it is not read as an inconsistency: the SCORE is what happened on the test — a blank is a lost mark; MASTERY is what the student knows — and it excludes unanswered from the denominator (FR-26) precisely so a parent can tell 'ran out of time' from 'does not understand'. Score is the result, Mastery is the diagnosis. Rejected: scoring over answered Questions only, which is consistent with the Mastery treatment but would require rewriting every worked example and both journeys and changes what a score means to a student; and showing both figures, which is honest but crowds the results header on a surface deliberately kept calm and low-stakes. URGENCY NOTED: this was the highest-damage finding in the review because Attempt records written under the wrong reading are not recoverable by a later fix — the arithmetic must be fixed in the PRD before any implementation begins.
- (decision) BLOCKER 3 RESOLVED (FR-4 vs FR-35, where review-consistency and review-child-safety disagreed): FR-35's uncommitted Parent View state is held SERVER-SIDE ONLY, with four consequences added to close the gaps that made both lenses uneasy. (1) The state — including captured Page Images, per-Question draft edits, draft review position, an in-progress grade override, and partial upload or classification steps — is stored server-side keyed to the Parent Account, never in client storage. This is what makes the applied FR-4 reading actually hold: 10 Security states that Student Mode restrictions are not client-side-only, so client-side retention would leave a route guard as the sole barrier while photographs of a child's schoolwork sat in the Student Mode origin's storage on a shared family tablet. (2) Restoration happens strictly AFTER PIN re-entry, never before. (3) A cross-profile fetch is rejected SERVER-SIDE — Pending drafts span Student Profiles per 6 while FR-34 binds to the last-bound profile, so without this the state of one child's draft can be stranded on a device a sibling is now operating, which is the cross-profile exposure FR-4 names directly. (4) A TTL applies so abandoned captures expire on their own clock. The TTL is not optional: FR-32's 90-day expiry starts at Source Test upload, which for this class never happened, and FR-33's deletion enumeration does not clearly reach it — without a TTL this is an indefinite store of children's schoolwork that no clock reaches and that only full account deletion removes, which would make 5.2's headline commitment false for this class of data. ALSO REQUIRED: FR-35 currently retains the FR-25 AI grading rationale, which FR-25 explicitly forbids surfacing to the student — the retained state must exclude it or guarantee it is unreachable in Student Mode. Rejected: server-side without a TTL, and narrowing FR-35 to exclude Page Images (smallest footprint but defeats the purpose, since capture is the step most likely to be interrupted in a kitchen).
